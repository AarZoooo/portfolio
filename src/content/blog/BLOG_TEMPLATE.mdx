## Shape

Use a short first section to state the context. Avoid turning the intro into a
tour of the page; the reader is already here.

Good posts on this site should feel like engineering notes that survived a few
rounds of deletion. Leave the useful parts. Cut the throat-clearing.

## Notes

Use lists when the rhythm needs them:

- One idea per bullet.
- Prefer concrete nouns over soft claims.
- Keep each item short enough to scan.

Use paragraphs when the reasoning needs a little air. The typography is tuned
for narrow reading, so dense prose will show quickly.

### Trade-off

When a post has a trade-off, name it plainly. For example, build-time work
keeps the browser quiet, but it can make the authoring path stricter.

> A good constraint should remove decisions, not hide them.
